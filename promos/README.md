# Plugin Store promo images

Marketing images for the Forklift listing on the Craft Plugin Store, rendered in the same theme as
the plugin's marketing page at
[justinholt.com/plugins/craft-forklift](https://justinholt.com/plugins/craft-forklift).

## Building

```bash
./build.sh          # all slides
./build.sh "2 5"    # just slides 2 and 5
```

Output lands in `out/` as `forklift-promo-N.jpg`, 1920×1080. Headless Chrome renders at 2× so the
type stays crisp and can only write PNG, so `sips` downsamples and converts to JPEG in one pass
and the PNG is deleted. **Promos are JPEG, never PNG.** Check `out/` holds only `.jpg` files.

## Keeping the numbers honest

The mocks share one customer, Acme Supply, and their figures agree with each other. Change one and
check the others:

- **Slide 2.** Trade list is 15% off: PL-1200 24.00 → 20.40, GL-L 6.00 → 5.10. Acme's sheet has
  HB-M10 fixed at 0.28 and CS-4 at 13.50 from 40, 12.75 from 100.
- **Slide 6** re-uses those prices (500 × 0.28, 40 × 13.50, 12 × 20.40).
- **Slide 5.** 8,400 + 6,250 − 8,400 + 4,980 + 3,120 = 14,350; limit 25,000 leaves 10,650. Aged at
  26 Sep with the payment settling #1041 (oldest first): #1133 current, #1102 31–60, #1058 61–90.
- **Slide 7.** $4,980.00 at Ohio's 5.75% is $286.35. The subtotal is invoice #1102's.

The only price in the deck is the cover badge, **Lite free · Pro $149**. A pricing change has to
reach it; see the pricing checklist in the marketing-site skill.

The reason sentences on slide 3 and the row errors on slide 6 are the plugin's own strings from
`src/translations/en/forklift.php`, except the `overCreditLimit` line, which is a paraphrase:
that reason withdraws the gateway rather than printing a sentence at checkout.

## Notes

The **watermark is an outline of the machine, without its load**. Filled, the counterweight is a
wide slab and the load a square block, and at 1180px across a slide either one reads as a
hard-edged grey box laid over the artwork rather than as a forklift — the same trap as Abacus's
frame bars and Bed's mattress. Outlined, the load would be a square frame, which is the same trap
by another route, so it goes entirely.

Two layout rules inherited from the rest of the family:

- **The copy column has to fit above the footer, and beside the panel.** The panel starts at
  `left: 870px`, the copy column is 700px inside a 130px gutter, and nothing clips — text that
  wraps simply lands on top. Three-line headings, two-to-four-line ledes, and one line per bullet
  (about 50 characters at 24px).
- **`.points li` is a flex container.** Every point keeps its text in one `<span class="t">`, or an
  inline element left loose becomes a sibling flex item and picks up the gap on both sides.

`fonts.css` is generated by `build.sh`, which base64-inlines the two woff2 files in `assets/` —
Chrome's `file://` origin rules block them otherwise. It is gitignored; don't edit it.

`assets/icon.svg` is a copy of `src/icon.svg`. Keep them in step.
